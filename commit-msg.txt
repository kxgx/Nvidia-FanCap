Fix power-limit drift and make the MSI task registration work on upgrades

Logic review fixes:
- power limit watchdog: another client (NVIDIA App auto-tuning stores 110 %) or a
  driver reload can change the limit unnoticed; compare it every 5 s and restore
  it (verified: external 200 W was pulled back to 150 W automatically)
- fixed mode: reclaim the manual fan policy before writing the speed, not after

MSI custom-action bugs found while testing the upgrade path:
- the condition "NOT REMOVE" is false during upgrades (RemoveExistingProducts
  sets REMOVE=ALL for the whole sequence), so the task was never registered on
  an upgrade; use "NOT Installed"
- a doubled ""path"" quoting inside cmd /c is split at the first space by cmd;
  use a single quote layer
- an immediate action ran before task.xml was copied (the old product's
  uninstall removes it, the new product's install copies it later); make the
  action deferred so it runs after all files are in place
- stop the old task, wait, re-create and start it, so a still-running previous
  instance cannot block the registration
